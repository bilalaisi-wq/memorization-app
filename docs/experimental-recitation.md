# Experimental recitation comparison (adult pilot)

This feature is **not certified Quran recitation or tajweed grading**. It does not verify makharij, madd, ghunnah, fluency, valid stops, or religious correctness. It never awards XP, stars, completion, mastery, or an FSRS grade. Puzzle correctness is deterministic word arrangement; recall grades remain learner self-assessments; AI output is a separate, uncertain transcription comparison.

## Current implementation and readiness

Active Recall → Hear your recall → **Experimental AI word comparison**. Record with browser microphone permission, stop, listen locally, declare that you have recited, check pilot access, and explicitly consent to submit your own adult voice. Local recording and original verified reciter playback remain available without AI, sign-in, or a paid plan. AI access does not restrict free Juz Amma learning.

The backend supports the existing source-validated free library and prepared private ayah bundles, enforcing content entitlements and integrity hashes. The current recording UI is in existing Active Recall; Passage Builder's separate passage/segment assessments do not submit partial recordings to this whole-ayah endpoint. No draft segment is presented as an AI reference or approved recitation stop.

The code and automated tests are implemented. **No live OpenAI request, hosted function deployment, privacy review, age-assurance review, teacher evaluation or production accuracy claim has been completed.** Without the server configuration and operator-approved adult pilot membership, uploads fail closed. Child uploads are not supported. Do not grant pilot membership to a child or to a shared account used by a child. Self-declaration alone is not age verification; the operator must review an appropriate adult approval process and prevent child access before activation.

## Data flow and model

1. Browser recording is held only as a Blob/object URL in this tab. Playback does not upload. Submission is separate and opt-in per recording; replacing or deleting a recording clears consent.
2. `recitation-compare` verifies the bearer token with `auth.getUser`, confirmed/nonanonymous identity, operator-approved adult membership, globally reviewed privacy/enable flags, AI-enabled paid entitlements and the source-derived juz permission. It ignores no client-supplied plan: unexpected fields are rejected.
3. The server loads the existing verified reference. It never accepts Quran text, expected words, user identity, model choice, bucket or storage path from the client. Free text uses the original `src/data.js`/additional library, bundled into the function; private text is downloaded with a pinned hash from the existing private bucket. Deploy the function with the matching source revision.
4. Streaming multipart reads stop at 8 MiB plus 32 KiB framing. File MIME and container signatures must agree (WebM, MP4/M4A, WAV, OGG or MP3). These checks reject obvious invalid uploads; they are not full codec validation or a media-security certification. The provider decodes the recording. A forged duration is never trusted from the browser.
5. A service-only SQL RPC takes a per-user transaction advisory lock; checks membership, flags and subscription again; enforces one pending request within 90 seconds, 10-second minimum spacing and 10 reservations/hour; then increments the UTC calendar-month allowance atomically. Defaults: Pathfinder 30, Guardian 60 (Guardian billing remains separately gated). Duplicated request IDs never call the provider twice. No user can reset or write usage. Paid access expiry and disabled flags immediately prevent new reservations.
6. Server-only `OPENAI_API_KEY` calls `https://api.openai.com/v1/audio/transcriptions`, model **`whisper-1`**, Arabic, `verbose_json`, temperature 0. Expected Quran text is deliberately **not** sent as a prompt. There are zero automatic retries, 10-second Supabase network timeouts, 20-second bounded body-read deadlines and a 35-second provider timeout. A timeout/failure may already have incurred cost, so its reservation remains consumed. Results are bounded to 256 KB, transcript 12,000 characters and 512 comparison words. Provider-reported duration must be positive and at most 120 seconds to assess; record at most two minutes for this experiment. Upload bytes are bounded before processing, but duration is not independently decoded before provider invocation: an overlong/forged clip can still incur a provider charge before abstention. Set provider project budgets/alerts; per-request cost is not guaranteed by the result-duration check.
7. Comparison-only normalization removes diacritics, tatweel and pause annotations, folds alef variants and final alif maqsura/ya, and filters non-Arabic characters. Original Uthmani text and spelling remain untouched. Ta marbuta/ha remain distinct. These folds can hide real differences; no vocalization or tajweed correctness can be inferred from an exact normalized match.
8. Bounded edit-distance alignment shows **possible** omitted/substituted/extra words. Sequence changes can appear as substitutions or omissions/additions; repetition alignment can be ambiguous. Empty/non-Arabic, grossly different, unsupported or weak transcripts abstain. Whisper segment thresholds (`avg_logprob < -1`, `no_speech_prob > .6`, compression ratio > 2.4) are conservative **uncalibrated screening heuristics**, not confidence percentages or validated Quran error probabilities. Confident hallucinations remain possible.
9. Learners can correct transcription locally and compare again. Corrections never replace reference text, train a model or alter learning records. An optional private category reports helpful/false-positive/false-negative/inaccurate/uncertain feedback; this is learner feedback, not teacher ground truth.

## Privacy, retention and deletion

- No raw audio, transcript or learner correction is stored by this app, Supabase Storage, progress backups or analytics. Uploads exist transiently in server memory and are sent to OpenAI only after explicit consent. Never enable gateway/request-body tracing, audio logging or third-party session replay for this flow. The handler does not log provider errors, tokens or request payloads.
- Server metadata includes model ID, provider version availability, comparison/policy/source hash versions, reference, outcome, difference count, provider duration, latency and an `evaluated:false` marker. The provider does not expose a pinned Whisper snapshot here; metadata explicitly says so. Quality flags are not calibrated probabilities. Identity, request ID, timestamps/state and usage counters enforce access/rate limits. Metadata and feedback are private service-controlled rows; no public leaderboard receives them.
- **Delete recording and analysis** aborts the local request, clears Blob URLs/transcripts/corrections and removes all this user's server analysis metadata/feedback. A delete during provider processing prevents metadata from being recreated by its eventual completion. Minimal non-content reservation ledger and quota counters remain so deletion cannot refill allowances. A request already accepted by the provider may continue after closing/deleting; this UI cannot revoke that processing or guarantee provider erasure.
- Run `purge_recitation_ai_metadata()` daily to remove request ledgers older than 30 days. Monthly aggregate counters persist until account deletion (needed for current quotas, minimal historical usage; apply a reviewed retention schedule if reducing this). Approved pilot membership persists until revoked/account deletion. Account deletion cascades to these AI tables, subject to existing billing closure rules. The provider and infrastructure may retain their own security/processing records; app deletion is not a claim of deletion from their systems/backups.
- Before enabling, publish the operator/contact, purposes, exact providers/regions/subprocessors, legal basis, retention, rights/request process and adult-only restrictions; review OpenAI API data-control/retention terms, Supabase/Railway logs, contracts and regional requirements. Do not promise zero provider retention or child-consent compliance. Use an API project with appropriate data controls and budget limits. This implementation is not legal certification.

## Cost estimate and provider documentation

Whisper is the initial baseline because its Arabic transcription endpoint provides structured duration and segment-level speech evidence for conservative abstention. This choice is not evidence that it is the most accurate model for Quran recitation. Evaluate newer transcription or specialized alternatives against the same held-out teacher dataset before changing models; version comparisons and thresholds separately.

Planning estimate for Whisper transcription: **US$0.006/minute**, approximately $0.0015 for 15 seconds, $0.003 for 30 seconds, $0.006 for 60 seconds or $0.012 for 120 seconds, excluding minimum rounding, infrastructure, taxes and provider changes. These are estimates, not billing guarantees. Verify current price, supported MIME/response fields, retention and account availability in the provider console before activation. Live provider docs could not be fetched from this environment (network proxy returned 403), so current terms/pricing have not been independently rechecked in this task.

References: [speech-to-text guide](https://platform.openai.com/docs/guides/speech-to-text), [pricing](https://openai.com/api/pricing/), [API data controls](https://platform.openai.com/docs/guides/your-data). A specialized validated Quran/tajweed model would require a separate evaluation and versioned change, not merely changing a frontend label.

## Teacher evaluation and launch evidence

**Teacher-reviewed false-positive/false-negative rates: not measured.** See the explicit [evaluation status](../content-reviews/recitation-evaluation-status.json). No reviewed audio dataset was provided. Synthetic unit fixtures and mock provider responses test logic, security and UI only; they provide no evidence of religious or real-world speech accuracy.

The offline evaluator accepts consented adult recordings already transcribed with the same model, plus independent qualified Quran teacher word annotations. Keep audio, transcripts and the manifest outside Git (e.g. ignored `.recitation-evaluation/`). It never uploads or changes Quran text. Each case contains:

```json
{"cases":[{"reference":"1:1","adultConsentReviewed":true,"audioSha256":"64_HEX_DIGEST_OF_CONSENTED_AUDIO","conditions":["clean"],"reviewer":{"name":"QUALIFIED_REVIEWER","credentials":"REVIEWED_CREDENTIALS","reviewedAt":"ISO_TIMESTAMP"},"teacher":{"errorWordIndices":[],"extraAfterWordIndices":[]},"provider":{"model":"whisper-1","transcript":"ACTUAL_PROVIDER_TRANSCRIPT","duration":5,"segments":[{"avg_logprob":-0.1,"no_speech_prob":0.01,"compression_ratio":1}]}}]}
```

Run `node scripts/evaluate-recitation.mjs /secure/path/teacher-reviewed-cases.json > /secure/path/aggregate-report.json`. The expected text comes from the authoritative source, not the manifest. Match the saved provider result to the hashed recording and retain its model/date/context securely for audit; the evaluator cannot independently certify reviewer qualifications or consent. Collect all conditions: `clean`, `background_noise`, `different_microphones`, `accents`, `pauses`, `repeated_words`, `intentional_omissions`, `incorrect_recitation`.

Reports include true/false positive/negative binary flags at expected word positions and insertion boundaries, rates, abstention/coverage and unassessed teacher errors, overall and by condition. Repeated edits at one boundary collapse to one flag; these are not phonetic or tajweed metrics. Abstentions are excluded from assessed confusion rates and reported separately to avoid misleading accuracy claims. Do not choose thresholds on the held-out evaluation set.

Before production: independently review qualifications/labels and inter-rater disagreements; use sufficient consented, diverse adult samples and held-out speakers/devices/ayahs; set acceptable false-positive/false-negative/abstention limits with teachers, report confidence intervals and subgroup results; evaluate long ayahs/repetitions, hallucination, feedback comprehension and normalization failures; obtain privacy/security review and actual provider staging results. Keep the feature off if evidence is insufficient. Child support requires a separate reviewed consent/access/privacy design.
