## Native toolchain/build attempts

This Linux environment has Node **24.19.0** and OpenJDK **21.0.12.1**, but no configured Android SDK/platform 36, `adb`, macOS or Xcode.

- `node scripts/native-build.mjs android-debug`: correctly stops because Android platform 36 is unavailable.
- Direct `GRADLE_USER_HOME=/tmp/ayah-native-gradle ./android/gradlew -p android :app:assembleDebug --no-daemon`: attempted, but Gradle distribution download failed with `UnknownHostException: services.gradle.org`. Even after network resolution, Android SDK installation is still necessary.
- `node scripts/native-build.mjs ios-debug`: correctly stops on Linux with the macOS/Xcode requirement. No iOS build was performed.

**No compiled APK, AAB, IPA, simulator run or physical-device success is claimed.** Signing keys/profiles/passwords were neither invented nor committed. Real builds and physical iPhone+Android tests are required before mobile readiness.

## External/operator release gates

Follow [README.md](README.md) for actual Supabase native redirect allowlisting, native CORS origins, existing Google Web OAuth callback, domain association files using real signing identities, Android SDK, Xcode 26/iOS SDK 26, signing and device tests. Native purchases/payment links are intentionally gated; in-app purchase/Apple Sign In, applicable store policy and active-subscription account-deletion behavior need release review before store submission. Native packaging does not itself certify licensing, privacy or store acceptance.

No Supabase migration is required. Existing website build/start commands and learning storage schemas are preserved. A new native installation is a separate app container; it must use existing account sync/export workflows to carry website progress rather than pretending to import browser-private storage automatically.
